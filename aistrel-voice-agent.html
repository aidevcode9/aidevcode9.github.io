Architecture Brief

Aistrel used concurrent voice tasks instead of one fragile loop.

This system was built for a harder class of AI workload than static prompt wrappers: real-time voice, provider churn, latency pressure, and the need to fail closed when guardrails or dependencies do not hold.

What this brief shows

  • parallel asyncio tasks for guarded voice behavior
  • provider fallback chains across STT, LLM, and TTS layers
  • fail-closed behavior when safety or timing conditions break
System Map

Six layers behind the real-time voice path.

The design assumes that latency, safety, and dependency failure all need dedicated handling. A single conversational loop is not enough for this class of system.

Stage 1

Live audio stream

Ingest audio continuously and keep the voice session responsive instead of blocking on one sequential pipeline.

Stage 2

Guardrail task

Run safety and policy checks in parallel so unsafe content can stop the response path before it is spoken back.

Stage 3

Intent task

Classify user intent concurrently so the system can route behavior without waiting for the final answer step to decide everything.

Stage 4

Response generation

Generate the response under guarded conditions and keep the model layer aware that fallback may become necessary.

Stage 5

Buffer manager

Handle streaming buffers carefully so the spoken experience stays coherent instead of jittery or broken under load.

Stage 6

Fallback chain

Shift across STT, LLM, and TTS providers when a dependency times out, degrades, or violates the fail-closed posture.

Build notes

The important signal here is not the use of voice alone. It is the system behavior under real-time constraints when multiple providers, asynchronous flows, and safety checks all need to stay in sync.

  • guardrails run in parallel instead of being bolted on after generation
  • provider fallback is treated as a first-class reliability pattern
  • timeouts and failures push the system toward fail-closed behavior rather than degraded nonsense
  • buffer management matters because voice UX breaks quickly when concurrency is sloppy

Core stack

  • Python asyncio concurrency
  • LiveKit session layer
  • Deepgram for STT options
  • Cartesia and ElevenLabs for TTS paths
  • GuardedLLM and fallback adapters

Signal: sub-2 second design target with guarded execution.

Shareability: architecture brief only, code remains private.

Latency

Real-time systems punish slow design.

Concurrency and buffer discipline are the difference between a voice product and a delayed demo.

Reliability

Provider churn is part of the architecture.

Fallback chains matter because production systems rarely get to assume one provider works perfectly forever.

Safety

Guardrails have to survive timing pressure.

The system is useful only if safety logic still wins when the pipeline is moving fast.
